# C++ Module 04

## Description

C++ Module 04 introduces subtype polymorphism, abstract classes, interfaces, virtual functions, and dynamic memory management in C++98.

The project is divided into four exercises:

### Exercise 00 — Polymorphism

Implements an `Animal` base class and the derived classes `Dog` and `Cat`.

The exercise demonstrates runtime polymorphism through virtual member functions. It also includes `WrongAnimal` and `WrongCat` to show what happens when a function is not declared as virtual.

### Exercise 01 — Deep Copy

Adds a `Brain` class containing an array of 100 ideas.

Each `Dog` and `Cat` dynamically allocates its own `Brain`. Copy constructors and copy-assignment operators perform deep copies so that different animals do not share the same `Brain`.

### Exercise 02 — Abstract Class

Changes `Animal` into an abstract class by declaring `makeSound()` as a pure virtual function.

As a result, `Animal` can no longer be instantiated directly, while derived classes such as `Dog` and `Cat` remain usable.

### Exercise 03 — Interfaces and Materias

Implements a Materia system using abstract classes and interfaces.

The main classes are:

- `AMateria`: abstract base class for Materias.
- `Ice` and `Cure`: concrete Materia types.
- `ICharacter`: interface representing a character.
- `Character`: character implementation with a four-slot inventory.
- `IMateriaSource`: interface for learning and creating Materias.
- `MateriaSource`: implementation that stores and clones Materia templates.

This exercise also focuses on resource ownership, cloning, deep copying, and avoiding memory leaks.

## Technical Choices

### Virtual Destructors

Base-class destructors are declared virtual so that deleting a derived object through a base-class pointer calls the complete destructor chain.

```cpp
Animal* animal = new Dog();
delete animal;
```

This correctly calls the `Dog` destructor followed by the `Animal` destructor.

### Deep Copy

Classes that own dynamically allocated resources perform deep copies.

For example, copying a `Dog` creates a new `Brain`:

```cpp
Dog::Dog(const Dog& other)
    : Animal(other), brain(new Brain(*other.brain))
{
}
```

This prevents two objects from owning and deleting the same pointer.

### Materia Cloning

The `clone()` member function creates a new object of the correct dynamic type:

```cpp
AMateria* Ice::clone() const
{
    return new Ice(*this);
}
```

This allows inventories and Materia sources to copy objects polymorphically.

### Ownership

A successfully equipped Materia becomes owned by the `Character`.

An unequipped Materia is not deleted automatically and must be stored or deleted elsewhere to avoid a memory leak.

A `MateriaSource` owns the Materias it successfully learns and deletes them when it is destroyed.
