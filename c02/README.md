# C++ Module 02

## Description

C++ Module 02 introduces ad-hoc polymorphism, operator overloading, and the Orthodox Canonical Form.

The goal of this project is to build a fixed-point number class in C++98 and gradually extend its functionality across four exercises.

The module covers:

- Orthodox Canonical Form
- Fixed-point number representation
- Integer and floating-point conversions
- Operator overloading
- Prefix and postfix increment/decrement
- Static `min` and `max` functions
- A two-dimensional `Point` class
- Testing whether a point is strictly inside a triangle

## Exercises

### Exercise 00 — My First Class in Orthodox Canonical Form

This exercise introduces the `Fixed` class with:

- A default constructor
- A copy constructor
- A copy assignment operator
- A destructor
- A getter for the raw fixed-point value
- A setter for the raw fixed-point value

### Exercise 01 — Towards a More Useful Fixed-Point Number Class

This exercise extends the `Fixed` class with:

- A constructor that accepts an integer
- A constructor that accepts a floating-point number
- Conversion from fixed point to `float`
- Conversion from fixed point to `int`
- An overload of the output stream operator `<<`

### Exercise 02 — Now We’re Talking

This exercise adds:

- Comparison operators: `>`, `<`, `>=`, `<=`, `==`, and `!=`
- Arithmetic operators: `+`, `-`, `*`, and `/`
- Prefix increment and decrement operators
- Postfix increment and decrement operators
- Static `min` overloads
- Static `max` overloads

### Exercise 03 — BSP

This exercise introduces a two-dimensional `Point` class and implements:

```cpp
bool bsp(Point const a, Point const b, Point const c, Point const point);
```

The function returns `true` when `point` is strictly inside the triangle formed by `a`, `b`, and `c`.

It returns `false` when the point:

- Is outside the triangle
- Lies on an edge
- Is equal to one of the triangle vertices

## Fixed-Point Representation

The `Fixed` class stores a number as an integer while assuming that eight bits represent the fractional part.

The number of fractional bits is:

```cpp
static const int _fractionalBits = 8;
```

The scaling factor is:

```text
2^8 = 256
```

To convert a real value to its raw fixed-point representation:

```text
raw value = real value × 256
```

To convert a raw fixed-point value back to a real value:

```text
real value = raw value ÷ 256
```

For example:

```text
5.5 × 256 = 1408
```

Therefore, the raw fixed-point representation of `5.5` is `1408`.

## Technical Choices

### Raw-Value Comparisons

All `Fixed` objects use the same number of fractional bits. Their raw integer values can therefore be compared directly without converting them to floating-point values.

For example:

```cpp
bool Fixed::operator>(const Fixed& other) const
{
    return (_fixedPointValue > other._fixedPointValue);
}
```

### Addition and Subtraction

Addition and subtraction can be performed directly on the raw values because both operands use the same scaling factor.

```cpp
result.setRawBits(_fixedPointValue + other._fixedPointValue);
```

### Multiplication

Multiplying two raw values also multiplies the scaling factor twice. The result must therefore be divided by the scaling factor once.

Conceptually:

```text
result raw = (left raw × right raw) ÷ 256
```

### Division

Before dividing two raw values, the numerator is multiplied by the scaling factor to preserve the fractional portion.

Conceptually:

```text
result raw = (left raw × 256) ÷ right raw
```

### Prefix and Postfix Operators

The prefix form changes the object and returns the updated object:

```cpp
Fixed& Fixed::operator++()
{
    ++_fixedPointValue;
    return (*this);
}
```

The postfix form returns the old value before changing the object:

```cpp
Fixed Fixed::operator++(int)
{
    Fixed oldValue(*this);

    ++_fixedPointValue;
    return (oldValue);
}
```

The unused `int` parameter distinguishes postfix from prefix syntax.

### BSP Algorithm

Exercise 03 uses the sign of a two-dimensional cross product to determine which side of each triangle edge the tested point lies on.

For each directed edge, the calculation is:

```text
(bx - ax) × (py - ay) - (by - ay) × (px - ax)
```

The result means:

- Positive: the point is on one side of the edge
- Negative: the point is on the opposite side
- Zero: the point lies on the edge

The point is strictly inside the triangle when all three cross-product results have the same sign.

- All positive: inside
- All negative: inside
- Mixed signs: outside
- Any zero value: on an edge or vertex, so the result is false
